🚀 Bringing Modern React to 3forge AMI

A Clean, Simple Approach That Actually Works

The Problem

3forge AMI is a powerful platform for building financial applications, but its UI components are... limited. Meanwhile, the React ecosystem has incredible libraries like AG-Grid, Highcharts, and D3 that would be perfect for trading dashboards.

❌What 3forge Developers Face:

  • Want modern UI components but stuck with basic native widgets
  • Need enterprise grids (AG-Grid) but can't easily integrate them
  • Want professional charts (Highcharts, D3) but no clean path
  • Forced to write custom Java plugins for simple UI needs

The question: Can we bring the entire React ecosystem into 3forge without massive complexity?

Why This is Hard

  • Style Isolation: 3forge's CSS can't interfere with React components
  • Single Runtime: React should load once, not per component
  • Simple API: 3forge developers shouldn't need extensive JavaScript knowledge
  • Bidirectional Data: Data needs to flow both ways seamlessly
  • Clean Deployment: Just drop a JAR, no complex setup

The Breakthrough

💡 "What if we just put React on the window?"

The solution turned out to be elegantly simple: Use Vite to bundle React as an IIFE (Immediately Invoked Function Expression) that exposes a global API on window.ForgeReact.

The Key Decisions

✅What Made It Work:

  1. IIFE Bundle: Vite builds React to a single JS file that runs immediately and exposes window.ForgeReact
  2. Shadow DOM: Each component mounts in its own Shadow DOM for complete style isolation
  3. Java Plugin: Simple plugin that injects the JS file and provides AmiScript API
  4. Clean API: react.mount('divId', 'ComponentName', props) - that's it!

Why This Works

  • Single React Runtime: Loads once globally, all components share it
  • No Build System for 3forge Devs: They just call a function, no webpack needed
  • Style Isolation: Shadow DOM prevents any CSS conflicts
  • Simple Deployment: Just one JAR with two JS files
  • Extensible: Add new React components without touching 3forge

Component 1: Vite Configuration

The magic starts with Vite configured to output an IIFE:

vite.config.ts
export default defineConfig({
  build: {
    lib: {
      entry: './src/main.tsx',
      name: 'ForgeReact',        // Global variable name
      formats: ['iife'],         // IIFE format
      fileName: () => 'forge-react.js'
    },
    rollupOptions: {
      output: {
        inlineDynamicImports: true,  // Single file
        globals: {}                   // No external deps
      }
    }
  }
});

Component 2: React Entry Point

The main.tsx file exposes the mounting API:

main.tsx
// Component registry
const COMPONENTS = {
  HelloWorld: HelloWorld,
  AgGrid: AgGridComponent,
  StockChart: StockChart,
  TraderDetailsCard: TraderDetailsCard
};

function mount(elementId: string, componentName: string, props: any = {}) {
  const element = document.getElementById(elementId);
  const Component = COMPONENTS[componentName];
  
  // Create Shadow DOM for style isolation
  const shadowRoot = element.attachShadow({ mode: 'open' });
  
  // Inject component CSS
  const styleElement = document.createElement('style');
  styleElement.textContent = COMPONENT_STYLES[componentName];
  shadowRoot.appendChild(styleElement);
  
  // Mount React
  const root = createRoot(shadowRoot);
  root.render(<Component {...props} />);
}

// Expose on window
window.ForgeReact = {
  mount,
  unmount,
  updateProps,
  components: Object.keys(COMPONENTS)
};

Component 3: Java Plugin

The plugin bridges 3forge's Java backend to the React frontend. It consists of two parts:

Part A: Java Adapter

Defines the AmiScript API and loads the JavaScript resources:

ReactGuiAdapter.java
public class ReactGuiAdapter implements AmiWebGuiServiceAdapter {
    
    @Override
    public String getAmiscriptClassname() {
        return "ReactGui";  // Available as __ReactGui in AmiScript
    }
    
    // Define methods callable from AmiScript
    @Override
    public List<ParamsDefinition> getAmiscriptMethods() {
        return CH.l(
            new ParamsDefinition("mountComponent", Object.class, 
                "String elementId,String component,Object props")
        );
    }
    
    // Load JavaScript resources
    @Override
    public List<String> getJavascriptLibraries() {
        return CH.l(
            "http://localhost:33332/resources/forge-react.js",      // React bundle (IIFE)
            "http://localhost:33332/resources/ReactGuiService.js"   // Bridge layer
        );
    }
    
    // Create the JavaScript bridge instance
    @Override
    public String getJavascriptNewInstance() {
        return "new ReactGuiService()";
    }
    
    // Forward AmiScript calls to JavaScript
    @Override
    public Object onAmiScriptMethod(String name, Object[] args) {
        this.peer.executeJavascriptCallback(name, args);
        return null;
    }
}

Part B: JavaScript Bridge

The browser-side bridge that connects window.ForgeReact to 3forge's peer system:

resources/ReactGuiService.js
function ReactGuiService() {
    this.peer = null;  // Will be injected by 3forge
}

// Required by 3forge - registers bidirectional communication
ReactGuiService.prototype.registerAmiGuiServicePeer = function(peer) {
    this.peer = peer;
    console.log("✅ ReactGuiService ready!");
};

// Called from AmiScript: __ReactGui.mountComponent(...)
ReactGuiService.prototype.mountComponent = function(elementId, componentName, props) {
    // Check if ForgeReact bundle loaded
    if (typeof window.ForgeReact === 'undefined') {
        console.error("❌ ForgeReact bundle not loaded!");
        return;
    }
    
    // Inject elementId for callbacks
    const propsWithElementId = {
        ...props,
        elementId: elementId
    };
    
    // Delegate to window.ForgeReact.mount()
    window.ForgeReact.mount(elementId, componentName, propsWithElementId);
    console.log("✅ Component mounted:", componentName);
};

🔑 Key Insight - The Two-Layer Bridge:

  1. forge-react.js (IIFE): Exposes window.ForgeReact.mount() - the raw React API
  2. ReactGuiService.js: Wraps window.ForgeReact and connects it to 3forge's peer system
  3. ReactGuiAdapter.java: Makes it accessible via __ReactGui.mountComponent() in AmiScript

This layering keeps the React bundle pure (no 3forge dependencies) while the bridge handles integration.

Component 4: 3forge Usage

3forge developers access the API through __ReactGui (registered in the Java adapter):

AmiScript in 3forge Dashboard (Div Panel)
// Get the ReactGui service instance
reactGui = __ReactGui;

// Mount a stock chart
reactGui.mountComponent('chart-div', 'StockChart', {
  symbol: 'BTC/USD',
  data: priceData
});

// Mount a data grid
reactGui.mountComponent('grid-div', 'AgGrid', {
  columns: columns,
  rows: rows
});

// Handle events from React components
onAmiJsCallback(element, action, data) {
  if (action == "rowClicked") {
    // Update other panels with selected row data
    trader = data.trader;
    
    // Update the trader details card
    reactGui.mountComponent('card-div', 'TraderDetailsCard', {
      trader: trader,
      desk: data.desk,
      total_pnl: data.total_pnl,
      trade_count: data.trade_count
    });
  }
}

📝 Note: The __ReactGui global is automatically available in all AmiScript contexts once the plugin is registered in ami-custom.local.properties:

ami.guiservice.plugins=com.forge.trading.ReactGuiPlugin

Example: Trader Details Card

A compact card that displays trader metrics from grid selections:

TraderDetailsCard.tsx
interface TraderDetailsCardProps {
  trader?: string;
  desk?: string;
  total_pnl?: number;
  trade_count?: number;
}

const TraderDetailsCard: React.FC<TraderDetailsCardProps> = ({
  trader, desk, total_pnl, trade_count
}) => {
  const isProfitable = (total_pnl ?? 0) >= 0;
  
  return (
    <div className="trader-details-card">
      <div className="card-header">
        <h3>📊 Trader Details</h3>
      </div>
      
      {!trader ? (
        <div className="empty-state">
          <p>Please select a trader</p>
        </div>
      ) : (
        <div className="card-content">
          <div>Trader: {trader}</div>
          <div>Desk: {desk}</div>
          <div className={isProfitable ? 'positive' : 'negative'}>
            P&L: ${total_pnl?.toFixed(2)}
          </div>
          <div>Trades: {trade_count}</div>
        </div>
      )}
    </div>
  );
};

Key Takeaways

The Bridge We Built

We didn't replace 3forge - we enhanced it. Native 3forge still handles queries, datamodels, and backend logic. But now, for the UI layer, you can leverage the entire React ecosystem without complex Java plugins.

🎯 The breakthrough: Stop fighting the system. Just put React on the window and call it a day.

Conclusion

Integrating React into 3forge doesn't have to be complicated. By using a simple IIFE bundle that exposes a global API, combined with Shadow DOM for isolation, we created a bridge that lets 3forge developers leverage the entire React ecosystem with a single function call.

What We Proved:

Organizations can keep their 3forge backend expertise while adopting modern frontend tooling. It's not React vs. 3forge - it's React and 3forge, working together through a clean, simple interface.
